# 使用与排障

## 配置项

完整配置模板见 [`.env.example`](../.env.example)。

| 配置 | 默认值 / 说明 |
|---|---|
| `QQ_TRANSPORT` | 新配置为 `official`；旧环境仅配置 OneBot token 时仍兼容 OneBot；可显式设为 `onebot` |
| `QQBOT_APP_ID` / `QQBOT_APP_SECRET` | `npm run login` 扫码保存，官方通道必填 |
| `QQBOT_ALLOWED_USER_IDS` | 官方通道操作者 OpenID，必填 |
| `QQBOT_ALLOWED_GROUP_IDS` | 官方通道群 OpenID，留空禁用群聊 |
| `QQBOT_ALLOW_PROACTIVE` | `false`；应用拥有主动消息权限后才开启 |
| `ONEBOT_WS_URL` | OneBot 模式使用，默认 `ws://127.0.0.1:3001` |
| `ONEBOT_ACCESS_TOKEN` | OneBot 模式必填，与服务 token 相同 |
| `NAPCAT_WEBUI_URL` | `http://127.0.0.1:6099`，仅供 `login:onebot` |
| `QQ_BOT_ID` | `npm run login:onebot` 保存的机器人 QQ 号 |
| `QQ_ALLOWED_USER_IDS` / `QQ_ALLOWED_GROUP_IDS` | 仅用于 OneBot 模式，数字 QQ 号/群号 |
| `QQ_GROUP_REQUIRE_AT` | OneBot 默认 `true`；官方通道只订阅群 @事件 |
| `QQ_PROGRESS_INTERVAL_MS` | 兼容旧进度组件的间隔 `15000`；交互工单改用 `/verbose` 折叠摘要，不逐条播报 |
| `QQ_SEND_INTERVAL_MS` | `1100`，QQ 出站最小间隔 |
| `QQ_MESSAGE_MAX_BYTES` | `3800`，每段 UTF-8 字节数，范围 256–3800 |
| `CLAUDE_WORKSPACE` | 必填，存在的具体目录绝对路径 |
| `CLAUDE_ALLOWED_PATHS` | 留空只允许工作目录，`*` 不限制 |
| `CLAUDE_PERMISSION_MODE` | `default`，另支持 `acceptEdits`、`auto` |
| `CLAUDE_MAX_TURNS` | `30`，交互工单单轮上限 |
| `TICKET_DB_PATH` | 官方默认 `data/qqbot-<AppID>.sqlite`，OneBot 默认 `data/tickets.sqlite` |
| `SESSION_TTL_MS` | `1800000`，内存会话缓存回收，不清除数据库 |
| `APPROVAL_TIMEOUT_MS` | `300000`，超时拒绝 |
| `READ_ONLY_TOOLS` | 默认 Read、Glob、Grep 等，见模板；显式留空可清空 |
| `DENIED_TOOLS` | 默认空；指定后各权限模式均禁止 |
| `BASH_READONLY_AUTO_APPROVE` | `true`，仅识别为只读的 Bash 自动批准 |
| `SCHEDULE_CONCURRENCY` | `4`，范围 1–32 |
| `SCHEDULE_MAX_TURNS` | `100`，范围 1–1000 |
| `SCHEDULE_DELIVERY_CONCURRENCY` | `4`，QQ 出站仍共享串行队列 |
| `SCHEDULE_TIMEOUT_MS` | `1800000`，包含审批等待 |
| `SCHEDULE_TIMEZONE` | `Asia/Shanghai`，IANA 时区 |

修改配置后重启生效。旧工单仍绑定创建时的工作目录，只修改 `CLAUDE_WORKSPACE` 不会迁移旧工单。

## 常见问题

**如何扫码绑定 / 二维码在哪里**

运行 `npm run login`，二维码直接显示在终端中，用手机 QQ 扫描并按页面提示确认机器人授权。无需 NapCat 或提前配置 AppSecret。旧 NapCat 入口为 `npm run login:onebot`，见 [NapCat 接入](NapCat接入.md)。

**扫码后还需要配置什么**

设置 `CLAUDE_WORKSPACE` 和 `QQBOT_ALLOWED_USER_IDS`。白名单使用 OpenID，不是手机 QQ 的数字账号。SDK 返回操作者 OpenID 时自动初始化白名单；若没有则用 `bootstrap-deny-all` 拒绝所有人。启动后发消息，可从拒绝日志获取自己的 OpenID，核实后填写并重启。

**扫码失败 / 取消后终端稍晚退出**

确认能访问 `q.qq.com`。Ctrl+C 会阻止保存新凭据，SDK 已发出的 HTTP 请求可能等待其自身超时（最多约 10 秒）才退出。二维码过期由 SDK 自动刷新。

**`node:sqlite` 无法加载 / npm 报 `node:path` 错误**

检查 `node -v`。本项目需要 Node >= 22.13，推荐 `nvm use 24`，切换后重新运行 `npm ci`。Node 的 SQLite 实验性提示本身不代表测试失败。

**一直重连或登录检查失败**

官方模式检查 `QQBOT_APP_ID`、`QQBOT_APP_SECRET`，以及 `bots.qq.com`、`api.sgroup.qq.com` 的网络。网关拒绝鉴权/事件权限时需检查机器人应用是否开放对应能力，修正后重启。OneBot 模式则检查 NapCat 登录态、服务地址与 token。

**显示已连接，但发送消息没反应**

官方模式检查 OpenID 白名单及事件权限；OneBot 模式检查数字 QQ 号白名单和好友关系。群聊须同时允许用户和群，并 @机器人。不会回复非白名单用户；官方拒绝日志会显示用户/群 OpenID，便于核对配置。

**QQ 无法格式化 Markdown / 进度没每条工具都显示**

这是纯文本传输，不支持点击展开或 HTML 折叠。发送 `/verbose on` 开启思考摘要与工具记录，默认只显示折叠入口；发送 `/verbose show` 查看，下一页用 `/verbose show 工单编号 页码`。开关按聊天保存，默认关闭，仅影响交互工单。仅展示 SDK 明确返回的思考摘要，不返回时不会编造。官方长任务可能超过回复窗口，执行结果仍保存，可发 `/history` 查看预览。

**普通文件发送失败**

发送 `/file ~/Downloads/report.pdf` 可绕过模型直接尝试发送，文件需在当前工作目录内且不超过 10 MiB。官方通道普通文件 `file_type=4` 尚未经过真实账号验证，可能被平台拒绝；OneBot 需要兼容文件上传扩展和 base64 输入。上传成功不等于对方收到，检查提示中的实际回执。目录需先压缩；普通文件接收暂不支持。

**审批没生效**

在发起审批的同一聊天发送完整的 `y 编号` / `n 编号`；定时任务用 `/schedule approve 编号` / `/schedule reject 编号`。群聊仍需 @机器人。工单切换、裸 `y` 或历史编号不能代替有效审批编号。

**QQ 发送失败 / 官方 API HTTP 或 code 错误 / OneBot retcode 非 0**

官方模式核对应用权限、被动回复窗口和次数、内容及频率限制。429 表示需降频；401 会清除缓存令牌，后续请求重新获取，但不会盲目重发当次消息。只有已获主动消息权限才开启 `QQBOT_ALLOW_PROACTIVE`。定时推送失败时结果留在数据库，可用 `/schedule history` 查询、`/schedule retry` 重发。OneBot 模式检查好友/群关系及 NapCat 日志。

**工单结果发送失败：被动回复窗口或条数已用尽**

桥接本地策略是收到消息后 4 分钟内、每个消息 ID 最多尝试 5 段回复，文字和附件共享额度。任务完成时窗口可能已过期，也可能额度已用尽；这不等于任务执行失败。重启新版桥接后，在原聊天发送 `/result 1` 取回工单 #1 最新已保存回复，按末尾“下一页”命令逐页读取，每条新命令会使用新的被动回复窗口。群里仍需 @机器人。此命令不调用模型，旧数据库的回复也能读取；无需为取回文字执行 `/resume`。

长交互结果现在只自动推送首页，全文仍保存。`/history` 每条只预览 500 字符，`/status` 只查看状态。主动推送开关不能授予平台权限，不能靠设置 `QQBOT_ALLOW_PROACTIVE=true` 保证绕过限制。

**发图片给机器人没有被分析**

确认已重启最新版桥接，群聊需 @机器人。图片必须通过 QQ 图片消息发送，暂不支持作为普通文件附件发送的图片。单条最多 4 张、每张最多 5 MiB；PNG/JPEG/GIF/WebP 以文件内容识别，SVG/HEIC 等请先转换。下载仅接受 QQ 官方 CDN 的 HTTPS 图片地址；过期链接、非 QQ 域名、网络失败会返回错误，需要重发。

**Claude 只回复了路径，没有收到图片**

先重启最新版桥接，让已加载进程更新代码。然后可直接发 `/image ~/Downloads/screenshot.png`，通过桥接发送文件，不依赖模型判断。也可要求 Claude“使用图片发送工具把这张图发回来”。图片应保存在当前工单工作目录内，而非临时目录或工作目录之外；确保未在 `DENIED_TOOLS` 禁用 `mcp__qq__send_image`。普通 Markdown 图片链接不会触发上传。新版将发图工具设为始终加载，并给恢复会话补充本轮能力说明，无需 `/reset` 清空历史。Claude 初始化时日志会显示“QQ 发图工具已加载”；未加载时也有明确提示。

**图片上传成功但发送失败 / 无法确认送达**

官方通道需要先上传取得 `file_info`，再发送图片消息，两个步骤都可能失败。图片和文字共用回复条数与时间窗口；生成耗时较长时，重新发消息要求回传文件。QQ API 的图片权限和上传方式仍需在真实账号上验证；只收到上传回执不会视作已发送成功。网络超时可能已经送达，重发前先看聊天记录。

**图片生成或截图工具不可用**

桥接新增的是图片输入和文件回传能力。生成图片、截图依赖 Claude 在本机可使用的脚本、浏览器或其他工具，不会仅因安装桥接就获得图像生成服务。

**达到轮数上限**

交互任务调整 `CLAUDE_MAX_TURNS`，定时任务调整 `SCHEDULE_MAX_TURNS`；先核查已完成操作再继续，避免重复执行。提高上限会增加模型用量。`/schedule retry` 只重发结果，重跑使用 `/schedule run`。

**重启后任务没有继续**

交互工单需 `/resume 编号`。定时任务已开始但中断的运行会标记中断，不自动重跑该次操作；后续周期继续，已生成待发送结果可恢复发送。

```text
src/

  images.js             QQ CDN 图片下载、格式/大小验证、本地图片读取

  file-tool.js          Claude 发送普通文件工具
  official-login.js    SDK 扫码回调、取消、凭据保存
  official-api.js      官方 Token、HTTP 请求和错误处理
  official-client.js   官方网关、心跳、Resume、回复窗口
  official-message.js  官方事件解析、OpenID 白名单、应用隔离
  onebot.js             WebSocket 鉴权、echo、重连、QQ 出站
  qq-login.js           扫码等待、浏览器入口与账号绑定保存
  qq-message.js         OneBot 事件解析、白名单、@、去重
  qq-progress.js        QQ 进度节流和最终结果
  ticket-bot.js         工单命令、串行执行、审批
  tickets.js            SQLite 工单和消息
  ticket-result.js      已保存回复全文分页、固定回复编号导航

  claude.js             Claude Agent SDK 会话
  claude-errors.js      SDK 错误与轮数上限
  approval.js           审批编号、等待和超时
  guard.js              工具/目录围栏
  bash-policy.js        只读 Bash 识别
  scheduler.js          定时命令、执行池、推送池
  schedule-store.js     定时任务持久化
  schedule-time.js      间隔、每日、单次规则
  schedule-delivery.js  文本分段及可选企微 Webhook
  config.js             环境变量解析和启动校验
scripts/login.js        官方机器人终端扫码入口
scripts/login-onebot.js NapCat WebUI 兼容入口
scripts/check.js        本地启动前自检
test/                  自动化测试
```
